## 2026-10-11 · 「环境与更新」页需求评审（SRS v1.4 → v1.5）

**评审方式**：grill-me 持续追问式评审，三轮共 10 问，全部收敛。输入：`docs/安装与更新需求.md` + `docs/功能参考脚本/` 四个 bat。

**背景**：v1.3 曾整体移除环境安装/更新功能（待重建），本次重建为「环境与更新」页（三标签页），启动器由"纯启动配置工具"升级为"安装器 + 启动器"。

### 已确认决策（11 条）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | Python 环境创建 | uv 建 `.venv`（替代 install.bat 的 python_env 方案）；Python 版本**钉死 3.12**（sageattention gfx1201 / bitsandbytes 为 cp312 构建）；补装 setuptools / wheel / mpmath |
| 2 | 镜像作用域 | **三分法硬规则**：GitHub 镜像仅作用于 git clone + GitHub release 轮子；PyPI 镜像仅作用于通用 PyPI 包 + 项目依赖；AMD 官方 index 永远直连（走镜像必 404） |
| 3 | ComfyUI 项目标签页范围 | 只管核心仓库（ls-remote 检查 + shallow clone + robocopy 热更新）；custom_nodes 不做；特殊轮子归轮子标签页 |
| 4 | torch nightly 失败处理 | 快照 + 回滚：更新前 `uv pip freeze` 快照，失败/取消可按快照重装恢复 |
| 5 | winget 提权 | 需提权时拉起 UAC 提权子进程执行 winget，完成后回普通权限；winget 不可用降级为手动引导 |
| 6 | 专用轮子清单维护 | 内置 JSON（wheel-catalog.json，类似 gpu-templates.json，随发版更新）+ 用户自定义补充（名称 + URL，持久化） |
| 7 | requirements 依赖同步归属 | 归入轮子标签页「项目依赖」分组（过滤 torch 系后 `uv pip install -r`） |
| 8 | GPU arch 检测 | Launcher 内置 WMI 显卡名称→arch 映射，不依赖 repo 已 clone / venv 可用；detect_gpu.py 仅作可选交叉验证 |
| 9 | 通用 PyPI 轮子交互 | 已装列表（uv pip list）+ 安装输入框 + 卸载 |
| 10 | 导航顺序 | 主页 → 配置管理 → 环境变量 → 启动参数 → 环境与更新 → 日志（现有页面顺序随之调整） |
| 11 | 任务互斥 | 全局单任务：装/更运行中禁用启动；ComfyUI 运行中禁用全部装/更；不排队不并行 |

### 作废的旧决策

- **附录 C「install.bat 不迁移（环境由用户用 uv 自建）」**：作废。install.bat 部分迁移（Python 环境改 uv venv 方案，专用轮子并入 wheel-catalog）。
- **NFR-4「启动器本体不做网络访问」**：修订为"无遥测；联网仅限 FR-8 用户显式发起的操作"。
- **v1.2 移除程序更新的理由（上游仓库已删除）转化为新约束**：仓库地址必须用户指定，不内置默认值。
- **v1.3 删除的 BusyEnv 状态**：恢复（环境任务中），并扩展互斥规则（决策 11）。

### 遗留风险（转入 SRS §8 风险表）

1. **uv venv 与上游 python_env 行为差异**：embeddable 特有配置（._pth 等）、rocm-sdk 在 venv 下的落盘布局未实测。实现前须先在 uv venv（Python 3.12）手工完整走通 install.bat 轮子流程作为验证项，不通过则回退复刻 python_env 方案。
2. **UAC 提权子进程与 GUI 的状态回传**：全方案实现复杂度最高的一块，用退出码 + 输出文件回传。
3. **AMD nightly / legacy 源结构变更**：wheel-catalog 数据驱动缓解。

## 2026-10-11 · 「环境与更新」复审（SRS v1.5 → v1.6）

**评审方式**：grill-me 复审，一轮 4 问收敛。挖出的 5 个问题：① 快照回滚承诺空心化（AMD nightly 旧 dev 版本会下架）；② FR-8.5「刷新主页版本显示」文档 bug；③ repo 更新每次全量 clone+robocopy 低效且自相矛盾；④ 新用户零到一动线无引导、导航顺序反直觉；⑤ 实现级坑（PATH 不刷新、检测时序、catalog 过时）。

### 已确认决策（4 条，其中 2 条推翻了前一轮）

| # | 决策点 | 结论 | 与前一轮关系 |
|---|--------|------|------|
| 12 | torch 回滚语义 | **下载验证门 + 尽力回滚**：`uv pip download` 全部成功才卸载（网络类失败时旧环境完整）；回滚=原版本可下则装回，下架则提示改装最新 nightly 恢复可运行 | 修正决策 4（快照回滚语义降级为"尽力"，承诺不再虚假） |
| 13 | repo 更新策略 | **双策略按目录形态分流**：是 git 检出 → `git pull --ff-only`（秒级）；非检出（zip 解压）→ shallow clone + robocopy；pull 失败可转强制覆盖 | 修正决策 3 的实现方式 |
| 14 | 导航顺序 | **主页 → 环境与更新 → 启动参数 → 环境变量 → 配置管理 → 日志** | **推翻决策 10**（环境与更新从第 5 位提到第 2 位，安装引导动线优先） |
| 15 | wheel-catalog 过时 | **仅随软件发版更新**（放弃自定义覆盖/联网刷新两条自救通道，用户明确接受）；轮子页显示清单版本标识提示 | 收窄决策 6 |
