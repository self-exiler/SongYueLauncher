## 二、高严重度问题（均已复验）

### H1. ~~退出清理残留 Python 进程功能静默失效~~ （已撤销）

> **更正（2026-10-17，经真机实测纠正）**：该结论不成立。`Process.Dispose()` 仅释放已缓存的句柄并置 `_associated=false`，**不清 `_processId`**；而 `Kill` / `WaitForExitAsync` 的状态校验只要求 `State.HaveId`，不检查 `_associated`——执行时句柄会按需用 `_processId` 重新 `OpenProcess`，因此对仍在运行的进程 `Kill(entireProcessTree: true)` 正常工作。会抛 `InvalidOperationException` 的是需要 `Associated` 状态的成员（`ExitCode` 等），`Kill` 不在其列。实测「结束 Python 并关闭」功能正常，与运行时行为一致。原论断「Kill 触发 EnsureAssociated 抛异常」有误，特此撤销。
>
> 残留一个**低危**代码问题转入 §四：`FindPythonProcesses` 在 `finally` 中对匹配项提前 Dispose，依赖「Kill 时隐式重开句柄」的行为，语义不清晰且存在 PID 复用窗口的理论风险，建议改为「不匹配才 Dispose」。

### H2. winget 安装后工具列表必然刷新失败

[EnvUpdatePage.xaml.cs](file:///c:/Users/dioha/OneDrive/project/ComfyuiLauncher/src/ComfyUiRocmLauncher.GUI/Views/EnvUpdatePage.xaml.cs#L186-L193)

```csharp
await App.Services.Tasks.Run(winget, ...).ConfigureAwait(false);
_tools = await ToolchainService.DetectAsync();
BuildToolList();   // 线程池线程直触 ToolList.Children
```

`ConfigureAwait(false)` 放弃 UI 上下文后，`BuildToolList()` 在线程池线程操作 `ToolList.Children.Clear()/Add`，抛跨线程异常；异常被 `RunOpAsync` 的 `catch (Exception)` 吞成一条 `[错误] <莫名信息>`。winget 安装必然耗时异步完成，**此路径 100% 触发**：用户装完 git/uv 看到的是错误提示，列表仍显示「未安装」。

- 修法：删掉 `ConfigureAwait(false)`（await 本就不阻塞 UI），或把 `DetectAsync` 之后的两句包进 `DispatcherQueue.TryEnqueue`。

### H3. torch 更新「验证通过」不可信

[WheelService.cs](file:///c:/Users/dioha/OneDrive/project/ComfyuiLauncher/src/ComfyUiRocmLauncher.Core/Services/WheelService.cs#L205-L212)

步骤⑥ `import torch` 验证的退出码被丢弃，随后无条件输出「√ ROCm / PyTorch 更新完成」并 `return true`。装错 arch、HIP 不可用时用户收到的是成功提示，GUI 依返回值也失去了提示回滚的最后机会，直接违背 SRS FR-8.5 步骤⑥的验证语义。

- 修法：捕获验证退出码，非零时输出失败原因并 `return false`（可走回滚引导）。

### H4. 单实例运行未实现

[App.xaml.cs](file:///c:/Users/dioha/OneDrive/project/ComfyuiLauncher/src/ComfyUiRocmLauncher.GUI/App.xaml.cs)

`OnLaunched` 直接 `new MainWindow()`；全工程无 `Program.cs`、无 `Mutex` / `AppInstance` 重定向任何单实例机制。SRS 2.3 明确「单实例运行」。多开实例各自持有状态机并并发写 `config.json`、可并行拉起多个 ComfyUI 与环境任务。

### H5. 发布管线无测试门禁

[release.yml](file:///c:/Users/dioha/OneDrive/project/ComfyuiLauncher/.github/workflows/release.yml) 全流程为 checkout → setup-dotnet → 装 WiX → `build.ps1` → 上传/Release；[build.ps1](file:///c:/Users/dioha/OneDrive/project/ComfyuiLauncher/installer/build.ps1) 内同样无 `dotnet test`。111 条测试在发布链路上完全不起作用，tag 一打即可带病出包。

- 修法：工作流中构建 MSI 前增加 `dotnet test -c Release`，失败即中断。

### H6. beta 与正式版 MSI ProductVersion 撞车，无法升级

[build.ps1](file:///c:/Users/dioha/OneDrive/project/ComfyuiLauncher/installer/build.ps1#L37-L41) 用正则截取数字段：`0.1.0beta` 与未来正式版 `0.1.0` 产出**相同**的 MSI ProductVersion。WiX MajorUpgrade 按「同 UpgradeCode + 更高版本」升级，版本相等时升级不触发，且因 ProductCode 冲突报「已安装另一版本」——beta 用户无法平滑升到同号正式版。

- 修法：预发布版本映射到独立修订号段（如 `0.1.0.100`），或正式发版时递增三位版本。

### H7. CTRL_BREAK 优雅停止从未生效

[ProcessService.cs](file:///c:/Users/dioha/OneDrive/project/ComfyuiLauncher/src/ComfyUiRocmLauncher.Core/Services/ProcessService.cs#L279-L305)

SRS 3.2 明确要求子进程以 `CREATE_NEW_PROCESS_GROUP` 创建「供 CTRL_BREAK 使用」，但 `CreateStartInfo` 未设置该标志（`Process.Start` 不暴露 CreationFlags，需 P/Invoke `CreateProcess`）。免打包形态下 python 子进程无控制台，`AttachConsole(pid)` 必然失败，优雅停止静默退化为「等 5 秒强杀进程树」。

- 影响：有兜底所以不会卡死，但 ComfyUI 每次都强杀，失去优雅关闭（缓存落盘、队列清理）的机会；实现与 SRS 不符。
- 修法：P/Invoke `CreateProcess` 携带 `CREATE_NEW_PROCESS_GROUP`；或修订 SRS 明确「当前形态仅强杀」。
